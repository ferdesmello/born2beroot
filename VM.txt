"minlen = 10

dcredit = -1

usercheck = 1
difok = 7"

minlen = 10: at least 10 characters.
ucredit = -1: at least one uppercase letter.
lcredit = -1: at least one lowercase letter.
dcredit = -1: at least one digit.
maxrepeat = 3: no more than three consecutive identical characters.
usercheck = 1: reject passwords containing the username.
difok = 7: require at least seven characters to differ from the previous password, subject to PAM's comparison rules.

Editing pwquality.conf defines the rules, but the PAM configuration determines whether password changes use them.

(the monitoring script)----------------
(disk and LVM layout) lsblk
(memory) free -m
(root filesystem usage) df -h /
(CPU count) nproc
(last boot time) uptime -s
(logged-in users) who

Requirement	Linux command or approach
OS and kernel architecture:	uname, /etc/os-release
Physical CPU count and vCPU count:	/proc/cpuinfo, nproc
RAM usage and percentage:	free
Disk usage and percentage:	df
CPU utilization:	vmstat or /proc/stat
Last reboot:	who -b or uptime -s
LVM active:	lsblk
TCP connections:	ss
Logged-in users:	who
IPv4 and MAC address:	ip
Sudo command count:	sudo log

We'll print the report using wall, which broadcasts a message to logged-in terminal sessions.

(create the file)
nano /usr/local/bin/monitoring.sh

"#!/bin/bash

ARCH=$(uname -a)
CPU_PHYSICAL=$(grep '^physical id' /proc/cpuinfo | sort -u | wc -l)
CPU_VIRTUAL=$(grep -c '^processor' /proc/cpuinfo)
RAM_TOTAL=$(free -m | awk '/^Mem:/ {print $2}')
RAM_USED=$(free -m | awk '/^Mem:/ {print $3}')
RAM_PERCENT=$(free | awk '/^Mem:/ {printf("%.2f"), $3/$2*100}')
DISK_TOTAL=$(df -h / | awk 'NR==2 {print $2}')
DISK_USED=$(df -h / | awk 'NR==2 {print $3}')
DISK_PERCENT=$(df -h / | awk 'NR==2 {print $5}')

# CPU utilization
CPU_LOAD=$(vmstat 1 2 | tail -1 | awk '{printf "%.1f", 100-$15}')

# Last reboot
LAST_BOOT=$(who -b | awk '{print $3, $4}')

# LVM status
LVM_STATUS=$(lsblk -o TYPE | grep -q lvm && echo yes || echo no)

# Established TCP connections
TCP_CONNECTIONS=$(ss -t state established | tail -n +2 | wc -l)

# Logged-in users
USER_COUNT=$(who | wc -l)

# IPv4 address and MAC address
IP_ADDRESS=$(ip -4 -o addr show scope global | awk 'NR==1 {split($4,a,"/"); print a[1]}')
MAC_ADDRESS=$(ip link show | awk '/link\/ether/ {print $2; exit}')

# Sudo commands logged
SUDO_COMMANDS=$(grep -c 'COMMAND=' /var/log/sudo/sudo.log 2>/dev/null)
SUDO_COMMANDS=${SUDO_COMMANDS:-0}

MSG="\
#Architecture: $ARCH
#Physical CPU: $CPU_PHYSICAL
#vCPU: $CPU_VIRTUAL
#Memory Usage: ${RAM_USED}/${RAM_TOTAL}MB (${RAM_PERCENT}%)
#Disk Usage: ${DISK_USED}/${DISK_TOTAL} (${DISK_PERCENT})
#CPU load: ${CPU_LOAD}%
#Last boot: $LAST_BOOT
#LVM use: $LVM_STATUS
#TCP Connections: $TCP_CONNECTIONS ESTABLISHED
#User log: $USER_COUNT
#Network: IP $IP_ADDRESS ($MAC_ADDRESS)
#Sudo: $SUDO_COMMANDS cmd

wall "$MSG"
"

$(...) runs a command and captures its output in a variable.
awk selects fields or performs calculations on command output.
wall sends the report to logged-in users' terminals.
nproc gives the number of processing units available to the system. In your VM, that should be 2.
vmstat 1 2 takes two samples one second apart. We use the second sample because it better reflects current CPU activity than the initial sample.
lsblk reports lvm if an LVM logical volume is present. The command checks for that type.
ss lists socket information; state established limits the count to established TCP connections.
who reports logged-in sessions, so this count is sessions rather than necessarily unique people.
grep -c 'COMMAND=' counts command records in the sudo log, not necessarily every command inside a shell session.

(signature)--------------------------------------
For Born2BeRoot, the important thing is to calculate the SHA-1 hash of your virtual machine's disk image, not the Debian ISO, the VM configuration, or signature.txt itself.

Important: Make sure the VM is fully shut down, not saved or suspended, before calculating the hash. Don't modify the disk between calculating the hash and submitting it.

certutil -hashfile "E:\ferde-so42\ferde-so42.vdi" SHA1
certutil -hashfile "M:\ferde-so42\ferde-so42.vdi" SHA1

certutil is a Windows utility.
-hashfile tells it to calculate a hash of a file.
SHA1 specifies the hashing algorithm.
SHA-1 produces a 160-bit digest, conventionally displayed as 40 hexadecimal characters.
